# Owner index

Search aliases plus links. The rule that decides a concern lives in the linked
guide, stack row, glossary entry or module docstring; this index only says where
to look. Rows name the owner symbol with its defining file, the governing rule,
and the applicability condition as that rule or docstring states it.

## How to search

```sh
grep -i "<keyword>" .agents/skills/angee-design/references/owners.md
```

Try the words a feature request uses (`archive`, `position`, `plugin`, `secret`)
and the column names an agent would reach for (`is_deleted`, `created_by`,
`parent`, `external_id`). A hit names the owner to read before writing; a miss
means search two nearby addons and the sibling slots before concluding no owner
exists. `tests/test_owner_index.py` checks the Owner column only: every cell carries
at least one `` `Symbol` path `` citation and no `path:line`, the cited file exists and
declares the symbol (a Python `def`, `class` or assignment target at any depth, or an
exported TypeScript or ES module declaration), so a citation survives moves within its
file; every public class an `angee.base.models`/`angee.base.fields` module declares is
cited at that module, and every `angee.*` addon (by name or a path in its folder) has
a cell. The rule and applicability columns are not checked. Guides are linked by
section anchor with the line in code text.
